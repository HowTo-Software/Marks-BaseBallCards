# Client data model and data meaning

**Status:** client contracts confirmed from source. **Updated:** October 3, 2026.

## Historical archive versus live inventory

| Dataset | Source | Fields/meaning | Updated by staff actions? |
| --- | --- | --- | --- |
| Public archive | [collection.json](../../src/Client/wwwroot/data/collection.json), loaded by [CollectionCatalog](../../src/Client/Services/CollectionCatalog.cs) | 64 records: card number, player name, rookie marker, Royals marker | No; committed historical snapshot |
| Live marketplace | [MarketplaceCardDto](../../src/Shared/Models/MarketplaceCardDto.cs) | Database ID, number/name, markers, price, condition, notes and sold state | Yes, through the backend |
| Staff inventory | [CardDto](../../src/Shared/Models/CardDto.cs) | Marketplace-related fields plus plastic storage, six filing flags, doubles, listing and recorded sale fields | Yes; protected API |
| Dashboard | [StatisticsDto](../../src/Shared/Models/StatisticsDto.cs) | Current totals, recorded sales value, six set-progress entries and generation timestamp | Computed by backend |
| Activity | [CardHistoryDto](../../src/Shared/Models/CardHistoryDto.cs) | Action, actor, timestamp, optional card ID and stored details | Written by backend |

The four archive fields were copied from the supplied
[seed](../../src/Api/Data/seed-cards.json). The original security review records a
workbook/seed comparison with no mismatches across its 12 mapped fields. That
historical review is preserved; it was not repeated in this documentation task.
See [DATA-01](../security/security-review.md#data-01--the-seeded-64-cards-are-not-the-full-1991-topps-base-set).

## Identifier and content rules

- `CardNumber` is a string label, not the database primary key. Search accepts name
  or number; number sorting uses numeric parsing with a fallback for other labels.
- `Id` identifies a live inventory row and is used for mutations and checkout.
- Rookie and Royals flags are collector annotations; no independent certification is implied.
- Art is generated by the local record component. No scan URL or physical-photo
  field exists in these client contracts.
- Condition, listing notes, names, card numbers and audit details are source-entered
  content. Changing the language does not rewrite them.

## Editing contract

[CardUpsertDto](../../src/Shared/Models/CardUpsertDto.cs) carries the editable inventory
fields. Its DataAnnotations define:

| Field | Declared validation |
| --- | --- |
| `CardNumber` | Required, maximum 20 characters |
| `PlayerName` | Required, maximum 120 characters |
| `Doubles` | Integer from 0 to 1,000 |
| `Price` | Nullable decimal from 0 to 1,000,000 |
| `Condition` | Maximum 60 characters |
| `ListingNotes` | Maximum 500 characters |

[AdminCards](../../src/Client/Pages/Admin/AdminCards.razor) additionally requires a
price above zero before listing a record. Client validation improves feedback;
server validation and current stock remain authoritative.

Six booleans `InSet1` through `InSet6` describe filing membership. `SetsFiledCount`
counts them for a record. `Doubles` is a separate recorded count; the UI does not
expand it into independent checkout inventory units.

## Statistics and units

Each `SetProgressDto` computes `CardsFiled * 100 / TotalCards`, rounded to one
decimal, or zero for an empty inventory. [The controller](../../src/Api/Controllers/StatisticsController.cs)
supplies the current database row count as `TotalCards`. The dashboard therefore
describes filing progress within current inventory, not completion of a canonical
Topps checklist.

Prices and recorded sale totals are displayed as USD, matching
[StripeOptions](../../src/Api/Payments/StripeOptions.cs). Locale affects numeric
separators, not conversion or the Stripe amount. A currency change requires
coordinating frontend labels/formatting with the backend.

## Authentication and checkout response contracts

[Auth models](../../src/Shared/Auth) define username/password requests and token,
username, role and expiry responses. No staff password is part of collection data.

[Checkout models](../../src/Shared/Models/CheckoutDtos.cs) return the hosted URL/session ID and
status/payment-status fields with optional card details. A return-page query
parameter is not evidence of payment; the status response is checked by the UI.
